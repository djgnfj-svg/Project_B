## 애니 규격 정본 (프레임 수·fps는 코드와 미러다)

| 대상 | 애니 | 프레임 | fps |
|---|---|---|---|
| 플레이어(방향별 e/s/n) | `idle_<d>` | 2 | 2.9 |
| | `run_<d>` | 4 | 9 |
| | `roll_<d>` | 4 | **16** (= `CombatMath.ROLL_TIME_S` 0.25s와 미러) |
| 잔몹 | `idle` | 2 | 2.5 |
| | `walk` | 4 | 7 |
| | `attack` | 3 | 8 (`ATTACK_ANIM_LEAD_S`와 미러) |
| | `death` | 3 | 7 |
| 보스(망령) | — | — | 🔴 **아래 「보스」 절의 표를 봐라** (여기 복제하지 않는다) |

🔴 **보스 애니 수치를 이 표에 복제하지 마라.** 2026-07-26에 여기 적힌 값(`swing` 5프레임 @12fps 등)이 시트보다 **하루 뒤처져** 있었고, 그 갈라짐을 실측으로 대조하다 결함 ③(공격 애니가 예고의 1/3에서 끝남)이 드러났다 — 즉 **이 표가 정확했으면 못 봤을** 결함이다. 정본은 언제나 `boss_wraith_frames.tres`이고(코드가 `sprite_frames`에서 읽는다), 아래 「보스」 절 표는 그 사본임을 명시한 참고용이다.
- ✅ **공격 애니 ↔ `telegraph_s` 어긋남은 해소됐다** — `boss.gd`가 `speed_scale`로 매 회차 예고 길이에 맞춘다(호스트 예고 길이가 RTT로 가변이라 `.tres` speed만으로는 원리적으로 불가능했다). 새로 그릴 때 지킬 것은 **"프레임수 ÷ speed ≈ 그 패턴의 `telegraph_s`"** 하나다 — 코드가 어차피 맞춰주지만, 어긋난 만큼 배율이 1에서 멀어져 동작이 늘어지거나 급해 보인다.

- 🔴 **4방향 명명 = `<base>_e` / `<base>_s` / `<base>_n`** (서쪽은 `_e`를 코드가 flip). **이름이 틀리면 코드가 2방향으로 조용히 폴백한다** — 에러가 없어서 "왜 4방향이 아니지"만 남는다(rules §5).
- 🔴 **애니 이름 집합은 엔진 호출부와 정확히 일치해야 한다.** 프레임 구성을 바꿔 이름이 사라지면 그 애니는 조용히 안 나온다. 클립을 손대면 리드에게 **`play("...")`·`autoplay` grep 대조**를 요청해라.
- 🔴 **`loop=false` 클립이 코드의 창보다 짧으면 마지막 프레임에 얼어붙는다.** 타이밍 상수(`ROLL_TIME_S`·`telegraph_s`·`swing_time`)를 건드리는 요청이면 **SpriteFrames speed도 같이 조정해야 한다고 보고해라**(반대도 마찬가지).
- **프레임 수를 늘리면 시트 폭이 늘어난다** → `_frames.tres`의 region 좌표가 전부 밀린다. PNG와 `.tres`를 **같이** 갱신해 리드에게 넘겨라. 한쪽만 고치면 애니가 조용히 깨진다.

**FX 캔버스를 바꿨으면 반드시 리드에게 "이 상수도 같이 고쳐야 한다"고 보고해라** — 안 하면 "맞는 곳 ≠ 보이는 곳"이 에러 없이 생긴다.

🔴 **보스 예고(콘·원)는 이제 텍스처가 아니다 — 그리지 마라 (2026-07-27).** `telegraph_cone.png`는 **삭제됐다.** 형태·각·반지름을 `assets/shaders/boss_telegraph.gdshader`가 `.tres`의 `range`·`half_angle`에서 직접 그린다(계약 = `projectb-rules` §3 「보스 텔레그래프 표시 기하」). 텍스처에 각이 박혀 데이터와 갈라지던 결함(68.6° vs 85.9° = **19px 무예고 피격**)의 근본 원인이 텍스처 자체였기 때문이다.
- ⚠ **부채꼴·원 모양을 그린 텍스처를 예고에 물리면 안 된다** — 알파가 셰이더 형태를 다시 잘라 정합이 깨진다. 지금 물려 있는 것은 코드가 만든 **1×1 흰 픽셀**이다.
- 🎨 **얹을 수 있는 것은 무늬뿐이고, 규격이 있다: 정사각 · 풀블리드(알파 1) · 중립색.** 예: 미세한 노이즈·격자·스캔라인. 셰이더가 이것을 곱하므로 형태는 그대로 두고 질감만 얹힌다. ⚠ 이건 **코드 변경이 선행된다**(`boss.gd`의 `_telegraph_quad_tex()` 교체) — 그릴 일이 생기면 리드에게 먼저 말해라. 없어도 현 상태로 완결이다.

## 무기 규격 (코드 계약)

무기는 **몸에 굽지 않는다** — 캐릭터와 분리된 독립 `Sprite2D`(장비 교체 = 텍스처 교체)다.
- **우향(+x) 수평** 기준으로 그리고, **그립(손잡이) 중심 픽셀 좌표를 보고에 반드시 명시**해라 — 코드가 그 점을 회전축(플레이어 손)으로 쓴다(`EquipDef.weapon_grip`).
- 코드가 360° 회전시키므로 **상하 대칭 실루엣**이 안전하다(셰이딩은 상단광 고정).
- 큰 무기는 `weapon_hold_dist`를 크게 잡아 몸과 겹치지 않게 한다(활 20).
- 저장 = `assets/sprites/weapons/<id>.png` + `assets/aseprite/<id>.aseprite` 소스.
- ⚠ **초보 장비에 속성·화려함을 얹지 마라**(사용자 확정) — 첫 지팡이는 무속성·무색 수정이다. 속성(불·얼음)은 상위 무기의 차별점으로 남긴다.
- ⚠ 투사체 텍스처(`projectile_texture`)는 **제 색으로** 그린다 — 탄에는 틴트를 곱하지 않는다(곱하면 탁해진다). 반대로 폭발·궤적은 중립으로 그려 틴트를 받는다.

## 🔴 Aseprite MCP 함정 (반드시 지켜라)

- **`filename`은 절대 경로.** 상대 경로는 서버 repo 디렉터리(cwd)에 떨어진다.
- **`draw_pixels`류는 기존 cel 경계 밖 픽셀을 조용히 버린다**(에러 없음). 회피: 테두리 `draw_rectangle` → 4변 `erase_region`으로 cel을 캔버스 전체로 확장한 뒤 그려라.
- **다프레임 캐릭터는 `run_lua_script`가 정답**: ASCII 픽셀맵(고정폭 문자열 + 문자→색 범례) + 부위별 맵(HEAD/TORSO/FEET) 조합·dx/dy 오프셋·mirror(문자열 reverse + L↔R 조명 스왑)로 프레임 일괄 생성. `assert`로 문자열 길이 검증 → `spr:newTag` + `frame.duration` → `saveAs`.
- **`run_lua_script` 에러는 `pcall(dofile, path)` + print로 받아라** — 실패 시 메시지가 빈 문자열이라 안 보인다.
- **검수 루프**: `export_frame scale 8` → Read로 이미지를 눈으로 확인 → 수정. 사용자에게 보여줄 땐 PNG 합본 후 리드에게 "Start-Process로 열어 달라"고 넘겨라.
- 🔴 **AI 이미지 인게임 직행 금지.** `mcp__imagegen__*`는 **컨셉·러프 용도로만** — 최종 도트는 aseprite로 손으로 다시 그린다.

## 🔴 산출물 경계 — 원본은 소스, 게임은 PNG/.tres

**`.aseprite`(원본)를 게임이 직접 참조하게 만들지 마라.** 원본은 `assets/aseprite/`에 작업 소스로만 두고, 게임이 보는 것은 항상 커밋된 **`.png` + `.tres`(SpriteFrames)** 다.

**왜 (실제 사고 2026-07-26):** `.aseprite`를 읽어주는 임포터 애드온은 **Aseprite 프로그램을 외부 실행**하고, 그 경로는 **EditorSettings(각 PC 로컬)** 라 커밋되지 않는다. 결과 — 만든 사람 PC에선 완벽히 동작하고(본인은 문제를 절대 못 본다), 다른 PC·심사위원이 클론하면 `Parse Error: referenced non-existent resource`로 **그 리소스를 쓰는 씬이 통째로 로드 실패**한다(실제로 챕터1 보스전이 안 떴다). ⚠ **웹 익스포트가 `exit 0`으로 통과한다** — 로그에만 ERROR가 찍힌다.

- 스프라이트 시트는 **PNG로 export**하고 애니 정의는 `assets/sprites/<모듈>/<id>_frames.tres`로 만든다(기준 예 = `boss_wraith_frames.tres`).
- 리드에게 넘길 때 **"이 PNG + 이 .tres를 커밋"** 이라고 명시한다. `.aseprite`는 소스로 함께 커밋해도 좋지만 **참조 대상이 아니다.**

## 작업 순서

1. 위 「규격 정본」에서 해당 대상의 캔버스·시트 구성·애니 프레임 수를 확인 → 기존 유사 에셋을 열어 색·밀도를 본다
