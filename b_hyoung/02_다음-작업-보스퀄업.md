# 다음 작업 — 보스 퀄리티 업 (인수인계)

> 이 세션 마지막에 논의하던 것. PC에서 이어서 하려던 방향.

## 결정된 축 (사용자 선택)
**아트/애니메이션 + 패턴/행동 AI** 두 축부터. 이펙트 퀄리티도 같이 고민 중(아래 참고).

## 도구 결정 (조사 완료)

### ✅ 아트/애니 = Aseprite Wizard (Godot 애드온) 도입 예정
- `.aseprite` 파일을 Godot이 **직접 임포트** → SpriteFrames 자동 생성. 태그(idle/attack/death)가 곧 애니.
- **현재 방식의 문제**: Aseprite MCP가 PNG 스트립 그림 → `*_frames.tres`를 **손으로 짬**(반복 노동). 프레임 늘릴 때마다 수작업.
- **웹 익스포트 무위험**: 임포트 타임(에디터)에서만 돌고 결과 .tres만 커밋. 런타임에 애드온 안 들어감 → 스레드 금지·class_name 캐시 제약에 안 걸림.
- 우리가 이미 `.aseprite` 소스를 만들고 있어 딱 맞음.

### ❌ 패턴/AI = 플러그인 쓰지 말 것 (조사 결론)
- Beehave(비헤이비어 트리)·LimboAI(FSM/BT) 있지만 **추천 안 함**.
- 우리 보스 AI = **호스트 권한 + 네트워크 동기화 + 데이터 주도(`BossPatternDef`)**. 이 애드온들은 로컬 런타임 전제 → 권한/동기화와 충돌.
- LimboAI는 C++ GDExtension → 웹 Compatibility 빌드에서 깨질 위험.
- 패턴 추가가 이미 ".tres 한 장"(rules §4)이라 플러그인 이점 없음. → **코드로 확장**이 정답.

## 계획된 순서

> **A(도구 세팅) → B(보스 몸+이펙트 아트) → 손맛 마감 패스**

### A. Aseprite Wizard 설치 (도구 세팅 — 다 깔고 감)
- 애드온 설치·활성화 → 망령 보스 `.aseprite`를 이 파이프라인으로 재임포트 → 애니 워크플로 자동화.
- 이후 프레임 추가가 전부 빨라짐 → B의 반복작업 가속.

### B. 보스 몸 + 이펙트 아트 (같은 Aseprite 파이프라인)
- 망령 공격/피격/사망 프레임 늘리기 + 입체 셰이딩(보류됐던 8방향 포함).
- **이펙트 "아트"는 B와 같은 파이프라인**: 공격 예고 장판·투사체·착탄 스프라이트·페이즈 오라. 지금 `telegraph.png` 한 장 틴트로 밋밋 → 제대로 그리기.

### 손맛 마감 패스 (엔진 내장, 플러그인 불필요)
- `src/feel` + 파티클(`particles-vfx` 스킬)·셰이더(`shader-basics` 스킬).
- 히트플래시·파티클 버스트·스크린셰이크·디졸브/광휘·페이즈 전환 연출.
- 보스 몸이 제대로 보인 **다음** 얹는 얇은 마감 층.

## 이펙트 퀄리티 — 사용자가 계속 신경 쓰던 부분 (타깃 미확정)
"이펙트 퀄리티 생각이 많다" → 아래 중 뭐가 제일 거슬리는지 정하고 B 브레인스토밍 타깃 잡기로 했음:
- [ ] 예고 장판이 조잡 (흰 원/콘 틴트 → 제대로 그린 룬/충격 예고)
- [ ] 착탄·타격이 안 시원 (파티클·셰이크·히트스톱 약함)
- [ ] 투사체/구슬이 밋밋 (물뿌리기·소울 구슬)
- [ ] 페이즈 전환 밍밍 (배너만 → 화면 연출·보스 오라 변화)
- [ ] 보스 몸 자체가 안 무섭다 (셰이딩·크기감·예비동작)

> **다음 세션 시작점**: A(Aseprite Wizard 설치)부터. 설치하면서 위 이펙트 타깃 정하고 → B를 brainstorming 스킬로 설계 후 착수.
