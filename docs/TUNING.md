# 튜닝 노브 — "이게 어색한데 어디를 만지지?"

플레이하다 어색한 게 보이면 **증상으로 이 표를 찾아** 그 줄만 고치면 된다. 전부 한 줄짜리 숫자 변경이고, 되돌리기도 쉽다.

> 🔴 **여기 있는 값은 전부 "아직 안 정해진 것"이다.** 헤드리스 테스트로는 결론이 안 난다(`projectb-verify` §6) — 직접 해 보고 느낌으로 정하는 수밖에 없다. 지금 몰라도 되고, 나중에 거슬릴 때 고치면 된다.
>
> ⚠ 값을 바꾼 뒤에는 `bash scripts/deploy_web.sh` 한 번이면 반영된다.

## 1. 화면이 너무 작다 / 크다

| | |
|---|---|
| **파일** | `src/feel/camera_rig.gd` |
| **상수** | `ZOOM` |
| **현재** | `1.0` (32px 캐릭터가 화면에서 32px = **원래 크기**) |
| **선택지** | `1.0`(현행 = 32px 아트 기준) · `2.0`(2배 — 16px 시절 보정값이었다) · `3.0` |

⚠ **`ZOOM`을 올리면 같은 파일의 `SHAKE_MAX`(7.0)·`KICK_MAX`(9.0)를 배율만큼 나눠라** — offset에 zoom이 곱해져 화면에 나가므로, 안 나누면 확대한 만큼 화면이 더 크게 흔들려 멀미가 난다(줌 2.0 시절 값이 3.5/4.5였다).

🔴 **정수만 써라.** 1.5·2.5는 픽셀이 뭉개져 흐릿해진다.

⚠ **줌을 올리면 같이 따라오는 것들이 있다** — 보이는 범위가 줄어들기 때문이다:
- 캐릭터가 **빠르게** 보인다 → §2
- 맵이 **넓게** 느껴진다 → §2
- **안 보이는 적**이 달려온다 → §3
- 화면 흔들림이 **커진다** → 같은 파일 `SHAKE_MAX`(현 3.5)·`KICK_MAX`(현 4.5)를 줌 배율에 반비례로 조정

## 2. 캐릭터가 너무 빠르다 / 느리다 · 맵이 넓다

| | |
|---|---|
| **파일** | `data/jobs/warrior.tres` · `archer.tres` · `mage.tres` |
| **값** | `move_speed` |
| **현재** | 전사 100 · 궁수 110 · 법사 90 |

16px 전환·복귀 양쪽에서 **일부러 안 건드렸다** — 월드 좌표(맵 크기)를 그대로 뒀기 때문이다. 줌도 1.0으로 돌아왔으므로 지금은 32px 시절과 **완전히 같은 체감**이다. 그래도 느리거나 빠르면 여기를 조인다.

⚠ 이걸 내리면 맵 횡단 시간이 2배가 된다(마을이 넓게 느껴진다). 반대로 맵을 좁히려면 `village.tscn`의 노드 좌표를 전부 줄여야 해서 훨씬 큰 작업이다 — **이동속도부터 만져 보는 게 맞다.**

## 3. 안 보이는 적이 달려온다

| | |
|---|---|
| **파일** | `data/enemies/goblin_melee.tres` · `brute.tres` · `chaser.tres` |
| **값** | `aggro_range` |
| **현재** | 고블린·chaser 140 · 브루트 220 · 보스 520 |

줌 1.0이라 화면 반폭이 **320px**이다 — 140은 화면 안에서 충분히 보이고 여유롭다(줌 2.0 시절엔 반폭 160px이라 아슬아슬했다). 그래도 화면 밖에서 걸린다고 느끼면 내린다.

## 4. 공격이 안 닿는다 / 너무 멀리 닿는다

| | |
|---|---|
| **파일** | `data/jobs/*.tres` |
| **값** | `attack_range` |
| **현재** | 전사 **42** · 궁수 **48** · 법사 **56** (2026-07-27 32px 복귀로 되돌아왔다) |

🔴 **이 값 하나가 판정·스워시 크기·검기 파형 도달점을 동시에 움직인다**(`CombatMath.effective_attack_range` 단일 소스). 그래서 여기만 고치면 "맞는 곳 = 보이는 곳"이 자동으로 유지된다 — **다른 데서 사거리를 따로 조정하지 마라.**

## 8. 보스 예고(빨간 장판)가 마음에 안 든다

전부 `src/enemies/boss.gd` 상단 const다. 2026-07-27에 **텍스처를 버리고 셰이더가 그리게** 바뀌었다.

| 증상 | 상수 | 현재 |
|---|---|---|
| 계단이 거칠다 / 너무 매끈하다 | `TELEGRAPH_PIXEL_PX` | 2.0 (월드 px — 줌 2배에서 화면 4px) |
| 테두리가 두껍다/얇다 | `TELEGRAPH_BORDER_PX` | 3.0 |
| 색이 안 보인다 / 너무 진하다 | `TELEGRAPH_FILL` · `TELEGRAPH_BORDER` | 옛 `telegraph_cone.png` 실측색 |
| 가장자리가 흐릿한 게 싫다 | `TELEGRAPH_FILL_FADE` | 0.25 (0 = 균일) |
| **깜빡이는 게 거슬린다** | `TELEGRAPH_PULSE_AMP` · `_HZ` | 0.10 · 2.2 (**0으로 두면 꺼진다**) |

🔴 **각·반지름을 여기서 키우지 마라 — 그런 상수는 아예 없다.** 예고 크기는 `data/enemies/*.tres`의 `range`·`half_angle`(= 판정값)에서만 나온다. 그래서 여기를 아무리 만져도 "보이는 곳 ≠ 맞는 곳"이 될 수 없다. 예고 범위 자체를 바꾸려면 그 `.tres`를 고쳐라(밸런스 변경이다).

⚠ `TELEGRAPH_PIXEL_PX`만은 예외적으로 **판정에 닿는다** — 격자를 키우면 안전 여유(`TELEGRAPH_EDGE_BIAS_PX`)가 자동으로 따라 커져서 예고가 그만큼 넓게 그려진다(항상 판정보다 **넓은** 쪽으로만 틀린다 = 무예고 피격은 안 생긴다). 8 이상으로 키우면 눈에 띌 수 있다.

## 아직 안 정한 큰 것 (결정이 필요할 때 보면 된다)

- **캐릭터 1개 + 무기가 직업** — 미착수. `job_id`가 하위 직업 **계열**의 뿌리라 GDD 변경(🔒 사용자 승인 후 리드가 `projectb-gdd` 스킬로 + `projectb-critic` 검증)이 선행 조건이다. 이번 개편의 최대 비용이고, 마감(2026-08-10)까지 남은 기간을 보고 정한다.
- **월드 좌표를 절반으로 줄일지** — 줄이면 화면이 32px 시절과 완전히 같아지지만, `village.tscn` 노드 좌표·마을 바닥 이미지·스폰 지점·맵 경계를 전부 변환해야 한다. §2 이동속도 조정으로 대부분 해결되는지 먼저 본다.
- **4방향 애니를 되살릴지** — 32px 복귀(2026-07-27)로 캐릭터가 단방향이 됐다. `player.gd`는 4방향을 지원하고 시트만 없으면 2방향으로 폴백한다. 살리려면 3직업 × 3방향 × 10프레임 재작화가 필요하다 — 마감(2026-08-10)까지 남은 기간을 보고 정한다.
- **보스 크기** — 망령 64px는 16px 캐릭터의 4배로 만들어졌는데 32px 캐릭터에선 2배다. "거대 보스" 인상이 약하면 시트 재작화(현 2368×64 / 37프레임).
