> **이 문서는 "무엇을 바꿨나"의 보관소**다. 판단 근거·교훈은 `docs/DECISIONS.md`, 기획은 `docs/GDD.md`, 일하는 법은 `CLAUDE.md`.
>

## 쓰는 법

새 항목은 **아래 「기록」 절 맨 위에** 다음 형식으로 쌓는다. 표가 아니라 **섹션**인 이유는 표 행에는 앵커가 안 생겨 `CLAUDE.md`에서 가리킬 수 없기 때문이다 — 가리킬 수 없으니 전문을 그쪽에 쓰게 되고, 그래서 CLAUDE.md가 부풀었다.

```markdown
## YYYY-MM-DD — 동사: 제목

**한 줄:** CLAUDE.md에 그대로 복사할 ≤200자 요약.

### 무엇을
### 왜
### 검증
### 남은 것
```

**세 곳의 분업 — 같은 내용을 두 번 쓰지 않는다:**

| 어디 | 무엇 | 길이 |
|---|---|---|
| `CLAUDE.md` 변경 이력 | 세션당 **한 줄 요약 + 여기 앵커 링크**, 최근 5건만 | **≤200자/건** |
| 여기 (CHANGELOG) | 무엇을 바꿨나 · 왜 · 검증 · 남은 것 | 무제한 |
| `docs/DECISIONS.md` | **되풀이하면 안 되는 판단**과 그 근거 | 무제한 |

길이·건수는 `bash scripts/check_harness.sh`가 검사한다. 손으로 지키려 하지 마라 — 07-21부터 규칙은 있었는데 최근 4건이 578~842자까지 부풀었다.

## 2026-08-01 — 추가: 전투 스테이지 전량 개편 (잡몹 3종 · 못 가는 지형 · 원거리 축)

**무엇을** — 챕터1 전투 2칸을 새로 만들었다. 잡몹이 고블린·브루트에서 **소·미노 검사·미노 궁수**로 바뀌고, 스테이지 바닥이 처음으로 `TileMapLayer`가 되면서 **물·낭떠러지라는 못 가는 지형**이 생겼다. 원거리 적이라는 축이 새로 열렸다.

**왜 이렇게** — 네 가지가 서로 얽혀 있었다.

⑴ **팔레트를 35 → 40색으로 늘렸다.** 사용자가 처음엔 "전부 35색"을 골랐지만, 실측 비교에서 미노 검사가 **올리브색 짐승**이 됐다. 35색은 숲 마을용이라 붉은 계열이 `#bf3f2e` 하나뿐이라 살빛 램프가 성립하지 않는다. 붉은 램프 5색을 더하니 원본에 가까워졌고, 결과를 보고 사용자가 확장을 확정했다. 매칭은 OKLab + 색상 가중 2.5 — 가중 유클리드는 살빛을 녹색으로 끌고 간다. ⚠ 미노 보스는 본체만 묶으면 안 된다. STELE 연출 중 시트를 갈아끼는 `mino_boss_c1.png`까지 해야 **연출 중에만 색이 튀는 것**을 막는다.

⑵ **통행 불가가 게임 코드 변경 0으로 붙었다.** 플레이어·잔몹이 이미 `collision_mask = 1`(world)이라 TileSet에 물리 레이어만 켜면 양쪽 다 막힌다. `gen_tileset.gd --solid`이 lower terrain의 **코너 단위 16×16** 콜리전을 깐다 — Wang 타일은 코너가 곧 지형이라 「그려진 물 = 못 가는 물」이 구조로 성립한다.

⑶ **씬 생성기를 파이썬으로 만들었다**(`scripts/gen_stage.py`). `tile_map_data`가 셀당 12바이트 `PackedByteArray`라 사람이 `.tscn`에 못 쓰고, 에디터로 그리면 재현이 안 되며 "어떤 지형이 통행 불가인가"가 씬에 파묻혀 리뷰가 안 된다. 🔴 **Godot `-s`로는 만들 수 없다** — 오토로드 전역 식별자를 컴파일 못 해 `stage.gd`·`stage_hud.gd`를 `load()`할 수 없고, 그대로 `PackedScene`으로 저장하면 그 노드들이 **스크립트 없이** 저장돼 런타임에 조용히 죽는다.

⑷ **원거리 잡몹은 두 안 사이에서 갈렸다.** 리드가 먼저 「예고 원 + 표시 전용 화살」을 구현했다(새 메시지 0 · 신뢰 경계 무변경). dev 설계는 「진짜 투사체」였고 사용자가 그쪽을 골랐다 — 화살이 실제로 날아와 맞고, 옆으로 비키거나 구르기 무적으로 피하고, 지형에 막힌다. 폐기된 구현은 `git checkout`으로 되돌렸다.

**원거리 축의 계약** (전부 `docs/DECISIONS.md`가 아니라 코드 주석이 정본)

- **단일 배우 유지** — 새 스크립트·씬 0개. `CombatMath.is_ranged_enemy(def)`가 판별의 단일 소스다(별도 bool 플래그를 두면 배우 분기와 트립와이어가 갈라진다). 새 원거리 적 = `.tres` 한 장 + 시트 한 장.
- **신규 kind 1개**(`G_MOB_SHOOT`) · 수치 전송 0 — `eid`만 싣고 각 클라가 자기 `EnemyDef`에서 리졸브한다. 사건 kind라 `RTC_FAST_KINDS` 제외. `aid` = `"m:<eid>:<seq>"`.
- **지연 보상 3축** — 조준은 기존 `strike_delay_s`, 표시 탄은 자기 편도만큼 **위치만** 앞당김(🔴 수명을 앞당기면 오차가 "안 보이는데 맞는다"로 부호가 뒤집힌다), 발사 애니는 `speed_scale`을 조준 창에서 유도(조준 창이 RTT 가변이라 고정 lead로는 원리적으로 못 맞춘다).
- 🔴 **쏜 화살은 사수 사망과 무관하게 날아간다** — 호스트는 `T_d`에, 게스트는 `T_d + 편도`에 죽으므로 수명을 사수 생존에 묶으면 한쪽만 화살이 사라진다.
- 🔴 **지형 차단은 호스트만** — 게스트가 스스로 지우면 호스트가 안 막은 경우에 「안 맞았는데 맞았다」가 된다. 소멸은 항상 호스트의 `G_ARROW_HIT`를 따른다. ⚠ 그 대가로 게스트 화면에서 화살이 벽을 편도 지연만큼 지나쳐 보인다 — **안전한 쪽의 어긋남**이다.
- **조준선**은 몸에서 **착탄점까지** 긋는다. 게스트의 `_aim_dir`은 근사라 방향으로 길게 그으면 게스트만 각이 어긋나는데, 착탄점은 `G_MOB_ATK`가 정확히 싣는다. 조준 시작에 고정되므로 **선을 보고 피할 수 있다**(GDD §5).

**두 번 밟은 함정 하나** — `mob_melee._physics_process`의 예고 카운트다운이 `is_dead()` 가드보다 **앞**에 있다(죽어도 예고가 제 수명을 마치는 기존 동작). 폐기된 구현에서 "죽은 궁수가 화살을 쏜다"로 밟았고, 조준선에서 "시체가 계속 조준한다"로 **다시** 밟았다. 둘 다 사망 가드로 막고 근거를 코드에 적었다.

**검증** — 스위트 10/10 · 데이터 트립와이어 6개 신설(배우·판정이 씬 글루라 `-s`가 preload 못 하는 구조적 사각이므로 규칙을 데이터 축으로 밀었다) · 실기 캡처로 조준선 → 발사 → 명중(HP 100 → 85 = 궁수 6 + 검사 9) 확인. 카이팅이 `keep_dist` 110에 정확히 멈추고, 걸으면 빗나간다.

**정리** — 안 쓰는 적·시트 48개 삭제. 🔴 도달 가능성을 재귀 추적했더니 71건이 나왔는데 대부분은 `GameState`가 **스캔 allowlist**로 런타임 로드하는 것들이었다(그대로 지웠으면 게임이 조용히 깨졌다). `enemies`만 씬 참조 전용이다.

**덤** — 화면 밖 남은 적을 가리키는 화살표(`src/hud/enemy_pointer.gd`). 표시 전용·네트워크 0. 거리는 크기가 아니라 **알파**로 표현한다(비정수 스케일은 픽셀아트를 뭉갠다).

⚠ **실기 미확인** — 웹 빌드 · 2인 배포본에서의 착탄 vs HP 감소 순서 · 물 건너 사격 차단 · 조준선의 게스트 정합. 전부 `dev_local.sh`(13.8ms)로는 재현되지 않는 갈래다.

## 2026-08-01 — 변경: UI를 판타지 나무·황동 픽셀 프레임으로 (전 화면)

### 왜

`docs/`의 문서가 **전부 영구 문서**여서 수명 있는 것(실행 계획·설계 스케치)이 갈 자리가 없었다. 그래서 영구 문서에 얹혀 살았다 — `TUNING.md` §11·§12·§13에 **날짜가 박혀 있고**(2026-07-28), §13은 "튜닝 노브"가 아니라 할 일 목록인데 소유권 표가 그걸 "다음에 무엇을 할 것인가"의 정본으로 지목하고 있었다. §13은 근접 모션이 끝나면 죽으므로 **정본이 사라질 예정**이었다.

삭제한 세 폴더는 "낡은 문서"가 아니라 **거짓 신호를 내는 문서**였다. `archive/`는 미완 체크박스 51건(WORKLIST 33 + QUALITY_BACKLOG 18)을 달고 있어 백로그처럼 보이는데, 코드를 찍어보니 대부분 이미 끝난 일이었다 — 체크박스만 안 채워졌다. 아무 정보도 안 주는 것보다 나쁘다. b-hyoung이 클론해서 열면 "할 일이 51개 남았구나"로 읽는다.

`archive/README.md`가 이미 "여기 있는 것은 정본이 아니다"라고 방어하고 있었지만, **방어문은 열어본 사람만 읽는다.** 그리고 그 README 자신이 규칙을 적어 뒀다 — *"다시 살릴 때는 문서를 되살리지 말고 갱신되는 자리에 옮겨 적어라."* 이번 회수가 그 규칙의 집행이다.
